03

What's actually new here

Not a wrapper, and not a demo of an existing tool with knobs bolted on.

01

Code, not pixels

Every visual is JavaScript drawing to a canvas, generated fresh by a model. No Imagen, no Veo, no diffusion model anywhere in this codebase — on purpose.

02

An agent, not a script

The Facilitator watches real telemetry — which tables are active, how long since anything changed — and decides when to act. Nobody scheduled a cron job.

03

Engine from scratch, content disclosed

The relay, the Facilitator, generation, audio-sync — all new. The default sketch library borrows 31 real templates from a sibling project, verbatim and credited, because the rules explicitly allow reusing templates as content. Said plainly here, not blended in quietly.

04

Legible, not statistical

Soft per-variable ownership means a change is always traceable to the table that made it — the piece never dissolves into an average nobody caused.

04

Against the actual rubric

One concrete proof point per official criterion — not a claim, a thing you can watch happen.

01Core Requirements & Functionality
The full loop runs today: knob press → relay → display → agent. Zero configuration required — a hand-written fallback sketch library means the app is fully demoable before a single API key exists.
02Innovation & Theme Alignment
Ask what's lost if the room is removed: everything. No single person, alone with a chatbox, can make this — it only exists because more than one set of hands is in it at once.
03Technical Execution & Integration
A relevant failure, handled live: a generation call fails or a table drops mid-event, and the shared display keeps running on the last known state — it never freezes because one of many inputs vanished.
04Usefulness & Agentic Experience
The user is the room itself: a venue full of strangers on their phones. The agent's job is turning shared physical presence back into shared attention — and keeping the piece alive all night without anyone running it.
05

What's real right now

Said plainly, because it's more convincing than an inflated claim.

Built & working

  • WebSocket relay with soft per-variable ownership
  • Prompt → OpenAI → validated sketch, with automatic fallback across the full built-in pool on any failure
  • 31 real p5.js templates inherited, normalized, and running live through the same relay — every default is real content, not a placeholder
  • Facilitator loop: telemetry → autonomous regeneration
  • Live display: runs either sketch contract, reads the room's mic, never freezes on a bad native frame
  • Table station: on-screen knobs generated from whatever sketch is live, plus a full-remix prompt box

Documented next step

  • Physical MIDI controllers as an alternative to on-screen knobs (Web MIDI API — the relay/station split is already shaped for this)
  • Per-table microphones, scaling a table's pull by how chatty it actually is — not just its knob presses
  • Audio-reactivity ported into the strongest inherited templates, not just fresh generations
  • A Jackbox-style join code on the display, so a phone types in rather than reads a URL off the wall
  • A visible per-table nudge from the Facilitator, not just a room-wide regeneration

Many hands. One canvas. Nobody runs it alone.
