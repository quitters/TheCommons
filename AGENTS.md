# Notes for coding agents

Read [README.md](README.md) first, then [docs/TEMPLATE_SCHEMA.md](docs/TEMPLATE_SCHEMA.md) before touching anything in `templates/`. Run `npm run verify` before and after any change — it boots the real server and checks the live API, not just static analysis.

Hard-won rules that are easy to get wrong here:

- **The 31 files in `templates/` are inherited content, not code to refactor.** They're copied verbatim from a sibling project, deliberately, for eligibility reasons documented in README's "What's inherited vs. built." Don't "clean up" their style, don't convert them to the native contract, don't delete the ones that look weird (`glorpy_heads.json` is supposed to look like that). `svg-flow-particles.json` is present but excluded from the auto-picked pool (`server/templates.js`'s `EXCLUDED` set) — it uses a p5 renderer mode (`SVG`) this project doesn't special-case; don't remove it from `EXCLUDED` without actually adding SVG-renderer support to `client/display/display.js` first.
- **Two sketch contracts exist on purpose, and they must not merge.** Native (`code`, plain Canvas2D, everything freshly generated goes here) and inherited-p5 (`p5Code`, p5.js instance mode, only the static library uses this). `server/generate.js`'s system prompt only ever asks for native — don't "improve" it into also emitting `p5Code` without reading why that was a deliberate choice (native is a smaller, more reliable target for on-the-fly generation) in `docs/inherited-p5-generation-prompt.md`'s header.
- **`[hidden]` vs. an ID selector that sets `display` — the ID wins, silently.** `client/display/index.html`'s `#p5Mount` rule is `#p5Mount:not([hidden]) { display: flex; ... }`, not `#p5Mount { display: flex; ... }`. The unconditional version out-specificities the browser's default `[hidden]{display:none}`, leaving a full-screen div invisible but still eating every click underneath it — this exact bug shipped once and was only caught by actually clicking the page, not by reading the code. If you add another `hidden`-toggled full-screen element, use the same pattern.
- **Bind the server to `0.0.0.0`, and use `127.0.0.1` in anything that connects to it locally, never bare `localhost`.** On this stack, `localhost` has intermittently resolved to IPv6 first while the server listens IPv4, causing connection timeouts that look like the server didn't start (it did — check the boot log). `server/index.js` and `server/smoke-test.js` both already do this correctly; keep it that way in anything new.
- **Variables are assigned automatically to individuals; excess participants share.** `server/relay.js` balances assignments on joins, departures, and replacement sketches. Opaque private session tokens identify participants, not public table labels. Keep the 30-second disconnect grace. When a variable is shared, its four-second hold makes each person's turn legible; do not replace it with averaging. On remix, clear queued input and rebuild controls and ownership from the new schema — names, types, choices, and ranges can all change.
- **Only the creator/admin can remix.** Enforce this on the server for both generation endpoints and job reads; hiding a station button is insufficient. `ADMIN_PASSWORD` grants an HttpOnly session at `/admin/`. Never send model keys or private participant tokens in room broadcasts.
- **Long generation belongs to a durable background job.** Save the prompt before calling a model and the result before publication. Reuse request IDs after reloads/lost responses, and never automatically repeat a paid call. A server restart preserves the prompt but cannot resume an unfinished upstream request. Gemini's long deadline must not become a browser HTTP deadline. Keep tests on injected responses/fallback mode, with autonomous calls disabled.
- **Remix and create are different operations.** Remix snapshots server-owned code/variables/current settings, while create sends no source context. Include mode in idempotency checks. Never obtain the remix source from arbitrary client-submitted code. Preserve compatible settings through the relay's validation. Durable undo restores the prior sketch and values without generation; keep native and inherited p5 runtimes separate even when p5 code is supplied as a generation reference.
- **Sliders require explicit numeric types.** Native numeric variables declare finite min/max/step/default values; preserve zero and actual numbers over the relay. Categories, including numeric-looking inherited text, remain choices. Do not rewrite inherited JSON to adopt numeric controls.
- **Visual identity lives in `client/shared/theme.css` and is shared with `pitch.html`.** Reach for those tokens (`--ground`, `--coral`, `--cyan`, `--font-display`/`--font-body`/`--font-mono`) rather than inventing new colors/fonts — the product and the pitch deck are meant to read as one thing. If a new page needs the theme, link both the Google Fonts stylesheet and `theme.css` the same way `client/station/index.html` and `client/display/index.html` already do, and make sure `server/index.js` actually serves whatever directory it lives in (a page referencing `../shared/theme.css` 404s silently if nobody added the matching `express.static` mount — this happened once, see the commit that added `app.use('/shared', ...)`).
- **This project never calls an image or video generation model.** Not Imagen, not Veo, not DALL-E, nothing — that's a scope decision stated repeatedly in README and the pitch deck, not an oversight to "fix" by adding one.
